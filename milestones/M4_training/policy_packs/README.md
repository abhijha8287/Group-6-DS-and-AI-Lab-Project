# Policy retrieval packs

These are AI-assisted draft materials awaiting human review. SunGrid and all S policies are fictional. No integration, write or outbound permission is created by these documents.

- `short/knowledge.md` and `large/knowledge.md` are separate retrieval documents. One F- or S-numbered table row is one retrievable section and chunk; R rows are the source register, not sections. Do not combine the packs during a single-pack evaluation.
- The short document contains the shared F1–F5 and S1–S10 sections. The large document preserves those rows exactly and adds fictional S11–S48 sections. S11–S34 clarify Solar policy distinctions, S35–S44 add office/procurement distractors, S45 sets precedence, and S46–S48 add conditional rules, dated versions and exceptions. Higher-level questions share one evaluator-only answer key in `questions.json`; added material increases retrieval complexity, not the answers to shared questions. Do not expose that file to the answering agent.
- Document IDs are `short/knowledge` and `large/knowledge`; section IDs are row IDs, and chunk IDs are `document_id#section_id`.
- `as_of` is 2026-11-19. Current policies are text in a snapshot, not an automated temporal engine; no runtime date filtering or version selection is implemented. S46–S48 explicitly describe historical versions and exceptions for manual review, not tested automated reasoning. Dates in the invented sections are fictional and are not claims about laws.
- The source register preserves historical access dates from the existing repository. These sources were not freshly reverified for this pack. External permissions and licenses are not established; `sources.json` records pending rights and factual review. The narrow inherited paraphrases are not source prose.
- `required_section_ids` identify the shared canonical core evidence. `relevant_section_ids_by_pack` additionally credit directly relevant alternative/partial evidence in the larger pack; generic cross-references do not count. Draft relevance sets are not certified exhaustive. Annotated relevance Recall@k, canonical-core coverage and any-relevant hit rate are separate metrics; none measures complete-answer correctness.
- The offline comparison indexes both facts and policies together. This differs from the existing agent pipeline's facts-only search plus policy system prompt; no default pack, scenario, CRM fixture or agent configuration is switched.
- Reproduce with `python3 scripts/preprocess_policy_packs.py --output <new-directory>`. The builder refuses overwrite, validates shared rows, rights/source references and question IDs, and records counts, approximate token estimates and SHA-256 hashes. `section_count` counts indexed F/S rows; Markdown heading counts are separate. Token estimates use characters/4, not a model tokenizer or billed usage.
- Question answers and annotations are AI drafts, not reviewed gold. `REVIEW_REQUEST.md` is assigned to the user, who selected “I'll review it myself.” Findings and approval remain pending; no completed review is claimed.
